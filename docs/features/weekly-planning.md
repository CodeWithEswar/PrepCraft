# Weekly planning

Weeks begin Monday in the workspace's IANA timezone. A week has extensible goal items (`study_time`, `question_count`, `revision_count`, `topic_completion`, `practice_session`, `behavioral_story`, `custom`) inside one relational weekly goal container. Targets express intent; they are not progress. Source measurements remain null until a real provider exists.

Set recurring weekday capacity and optional date exceptions first. Goal-based generation uses real effective curriculum topic IDs and a versioned estimate policy, not an invented question library. Question goals create small intent batches with count metadata; checking off one task does not record question attempts or topic mastery. Revision counts cannot create obligations without Revision data.

Build weekly plan opens a proposal. Review the task changes, reasons and before/after daily loads before Apply. A proposal with unplaced work, oversized goals or overloaded protected days cannot be activated. Existing work remains untouched until the transaction succeeds. Rebalance redistributes flexible unfinished work; completed, active, source, deadline and scheduled-window obligations are protected. There is no hidden automatic carryover or optional-task deletion.

Limits: 20 goal items, 100 stored task rows per day, 100 proposal changes, 5–480 minutes per atomic task, up to 720 minutes of daily availability. Very large goals stay explicit conflicts rather than being silently truncated. Proposals are ephemeral diffs; relational rows remain the authoritative plan.
