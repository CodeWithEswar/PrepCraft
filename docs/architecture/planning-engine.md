# Deterministic planning engine

`src/features/planning` separates portable capacity/allocation/review services, DTOs and Zod commands from server-only queries/mutations and client views. The server resolves the live workspace and membership, reads bounded relational data and effective curriculum, then seeds TanStack Query under `["workspaces", workspaceId, "planning", week]`. The existing workspace-switch cache boundary removes these keys. Mutations invalidate the related Today aggregate.

Policy `capacity-v1` protects fixed, active, completed and source obligations. Generated work prioritizes evidenced weak core topics (only when a real Mastery port provides evidence), curriculum priority, track weight and stable identity. Required work precedes optional work. Flexible tasks are assigned to days with enough whole capacity, choosing the lowest load ratio then date. Atomic tasks are never forced into a smaller gap. Generation can split a user-defined time goal into valid preparation blocks; source tasks remain atomic.

The pure proposal includes the workspace context version, planning revision, before/after load, protected IDs, changes, unplaced work, reasons, assumptions and a deterministic fingerprint. The fingerprint is an equality check, not an authorization credential. The server recomputes it from authorized inputs before persistence; SQL independently authorizes, checks versions, constraints, protected work and final capacity in one transaction.

`planning_state.revision` is a monotonic workspace concurrency token. Triggers bump it for schedule, availability, goal, review and preparation-context writes, including Today execution changes. Snapshot reads compare versions before and after aggregation. A changed aggregate fails visibly rather than mixing revisions. Request UUIDs and canonical payload hashes make retries idempotent; reusing an ID for another payload/actor fails.

Optional evidence providers use `PlanningEvidencePorts`. Providers receive the authorized workspace/timezone/bounded date scope. Scope mismatches and individual provider failures produce error states. Focus intervals are validated, unioned and split at local midnight. Revision adapters refer to source-owned existing projections; this feature does not manufacture revisions. No new Cloudflare queue, cron, D1, KV or realtime subscription is needed. Existing allowlisted structured server logging covers success, rejection and failure; no Sentry DSN is configured in this repository, so telemetry is not claimed to be delivered externally.
